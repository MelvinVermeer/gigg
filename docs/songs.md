# Songs (repertoire)

Fixed fields: title, duration, key, BPM, tuning/instrument changes, notes (markdown), lyrics (markdown), tags.

**Lyrics**: markdown like notes, line breaks kept as typed. Only on the song page (after notes, under a “Lyrics” heading, left out when empty) and in the song form; not in the songs list, search or the shown-fields grid. They do travel with setlists, for the lyrics show mode (see [setlists.md](setlists.md)).

**Custom fields** (Settings → Songs): single-line text fields the band adds to every song ("Lead vocal", "Capo"). Members add, rename (on blur / Enter) and archive/restore them; readers see the list. Names: up to 40 characters, unique per band ignoring case (archived ones included), not a fixed field's name in any language; shown as typed, not translated. No reordering: creation order. Values: optional, up to 100 characters, one line; in the song form after the fixed fields (before notes), on the song page like the fixed fields ("–" when empty). Archiving a field hides it everywhere but keeps its values (the form doesn't send archived fields, the server keeps their values). Not in the songs list or search. Files attached (lyrics, recordings, sheets); see [files.md](files.md).

**CSV import / export** (Settings → Songs; logic in `lib/song-csv.ts`, shared by the dialog and the `importSongs` op). *Export CSV* (readers too): the active songs with every fixed field, then custom fields by name, tags joined with commas; semicolons + BOM like the setlist CSV. *Import* (members, online): upload a file or paste; `,` `;` and tab all work, quoted cells may span lines; the delimiter is the one most lines have, so a plain list of titles works too (every line a song, "Hello, Goodbye" stays whole) unless its first line is a title header. On the songs page members can also drop a CSV file on the song list (or the empty state, which also has an Import button): it opens the dialog at the mapping step, and the summary there points to dropping more or Settings. A mapping step always comes first: per column a guessed target (fixed field names in EN/NL plus synonyms such as song/naam/tempo/duur, the band's custom fields by name, `#`/nr skipped, anything else → "add to notes"), the value from the row with most cells filled, and how many values aren't understood. Targets: a field, a custom field, a new custom field named after the header (up to 40 characters), add to notes (as `Header: value` lines, also on existing songs with fill or overwrite, never twice), skip. A title column is required, and no two columns may go to the same field. Existing songs match on title ignoring case and spacing, archived ones included (those are always skipped); the choice is skip (default) / fill empty fields / overwrite, and an empty cell never clears a field; a song with nothing to change counts as skipped. Duplicate titles in the file: the first wins. Durations 3:45, 1:02:30 or seconds; BPM 120 or "120 bpm"; tags split on `,` and `|`, lowercased. A value that isn't understood is left empty and listed in the summary (created / updated / skipped), only for songs that were written; a title that isn't understood skips its row and is listed too. The whole import is one transaction, so one change in the history.
