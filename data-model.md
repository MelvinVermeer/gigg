# Gigg: data model (draft)

Postgres. Every band-owned table has `band_id`. IDs are UUIDs; URLs use slugs.

## Conventions

- `archived_at timestamptz` on every user-facing entity. "Delete" in the UI = set `archived_at`. Restore = clear it.
- Child rows (set items, block songs, gig contacts) are plain rows: they're replaced on edit, and the audit trail keeps the history.
- Slugs are unique per band per type, **including archived rows**, so restoring never collides.
- Auth tables are generated by Better Auth (passkey + magic-link plugins).

## Schema

Source of truth: [`src/server/db/schema.ts`](src/server/db/schema.ts) (app tables) and
[`auth-schema.ts`](src/server/db/auth-schema.ts) (generated by Better Auth: `users`, `sessions`,
`accounts`, `verifications`, `passkeys`).

Tables: `bands`, `memberships`, `slug_redirects`, `songs`, `venues`, `contacts`, `gigs`,
`gig_contacts`, `setlists`, `sets`, `set_items`, `blocks`, `block_songs`, `files`, `feedback`, `changes`.

Decisions made while building:
- **Child tables have `band_id` too** (`sets`, `set_items`, `gig_contacts`, `block_songs`), so every audit entry has a band and every query can filter on band.
- `slug_redirects` has its own `id`; uniqueness is `(band_id, type, old_slug)` with nulls not distinct (band slugs have no band).
- `users` comes from Better Auth; anonymisation (`anonymised_at`) is added when member removal is built.

## Audit trail: a Postgres trigger

One generic trigger function on every table (except auth internals) writes to `changes`. See `drizzle/0002_audit.sql`. The app sets the user per transaction:

```sql
select set_config('app.user_id', $1, true);  -- true = transaction-local
```

Why a trigger and not app code: it can't be bypassed (migrations, scripts and manual fixes are logged too), and it's one function instead of a rule every developer has to remember. Archive/restore shows up as an `update` where `archived_at` changes.

## Search

`pg_trgm` GIN indexes on `songs.title`, `gigs.name`, `venues.name`, `contacts.name`, `files.name`. One `UNION ALL` query returns typed results ranked by `similarity()`.

## Offline

One server function returns all non-archived rows for the band. It's a TanStack Query query whose cache is persisted to IndexedDB, refreshed when online. Files are cached on open.

## Dev mode

PGlite (Postgres in WASM) supports triggers and `pg_trgm`, so dev mode runs on a local file with no Docker and no cloud database. A seed script fills it with a fake band.
