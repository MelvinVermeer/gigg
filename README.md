# Gigg

Gigs, setlists and riders for bands. Installable PWA. See [idea.md](idea.md) and [data-model.md](data-model.md).

## Develop

```sh
pnpm install
pnpm dev          # http://localhost:3000, no accounts or database needed
```

Without `DATABASE_URL` the app runs in **local mode**: Postgres in WASM (PGlite) in `.pglite/`, migrated and seeded on start. Sign in as `member@example.com`, `reader@example.com` or `admin@example.com` (admin: `/admin` in the user menu); the sign-in link is printed in the console. Delete `.pglite/` to start fresh. A production build (`pnpm build && pnpm start`) refuses local mode unless `LOCAL_MODE=1` is set.

## Test

```sh
pnpm typecheck
pnpm test         # Vitest: server logic against in-memory Postgres
pnpm test:e2e     # Playwright: production build in local mode
```

CI runs all three on every PR and every push to `main`.

## Text and languages

All UI text lives in `src/lib/i18n.en.ts` (the source) and `src/lib/i18n.nl.ts`; the type check fails when Dutch misses a key, and `src/lib/i18n.test.ts` fails on English typed straight into a page or component. Components get the dictionary with `useT()`. The manual (`src/routes/manual.tsx`) is prose per language. Errors the UI shows are thrown by key (`errors` in the dictionary).

## Database

- Schema: `src/server/db/schema.ts` (app) and `auth-schema.ts` (generated by Better Auth).
- After a schema change: `pnpm db:generate`, commit the migration in `drizzle/`.
- New table? Add it to the trigger list in a migration (see `drizzle/0002_audit.sql`); a test fails otherwise.
- Production: `DATABASE_URL=... pnpm db:migrate`, or the CI `migrate` job (see Self-host on Vercel). Keep migrations additive.

## Self-host on Vercel

1. Fork the repo and import it in Vercel; the framework is detected. `vercel.json` pins the region to `fra1`: change it to one near your database and users. Every page is marked noindex (`X-Robots-Tag` in `vercel.json`, a robots meta tag in `src/routes/__root.tsx`); remove both if you want search engines.
2. Add Postgres: Neon from the Vercel Marketplace sets `DATABASE_URL`. Without it a Vercel deploy refuses to start.
3. Add a Blob store (Storage tab); it sets `BLOB_READ_WRITE_TOKEN`. Without it uploads fail. Files up to 100 MB each.
4. Set the environment variables (`.env.example` explains each):
   - `BETTER_AUTH_URL`: the public URL, no trailing slash.
   - `BETTER_AUTH_SECRET`: `openssl rand -base64 32`.
   - `ADMIN_EMAILS`: your email.
   - Email: `RESEND_API_KEY` (or `SMTP_URL`, which wins), and `MAIL_FROM` on a domain verified with that provider. Unset, it sends from `no-reply@` the host of `BETTER_AUTH_URL`.
   - Optional: `OPEN_SIGNUP`; `BAND_STORAGE_LIMIT_MB` (storage per band, no limit when unset); push with `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` (`npx web-push generate-vapid-keys`) and `VAPID_SUBJECT`; feedback as GitHub issues with `GITHUB_REPO`/`GITHUB_TOKEN` (in a public repo the feedback text is public).
5. Migrate the database before the first deploy, either way:
   - Locally: `DATABASE_URL=<Neon direct (unpooled) URL> pnpm db:migrate`.
   - In CI: add the repo secret `DATABASE_URL_UNPOOLED` and enable Actions on the fork; the `migrate` job then runs on every push to `main`. Without the secret that job fails.

   Vercel deploys in parallel with the migration, so keep migrations additive.
6. Custom domain: add it in Vercel, set `BETTER_AUTH_URL` to it and redeploy.
7. Sign in with an `ADMIN_EMAILS` address and create bands from `/admin`.
